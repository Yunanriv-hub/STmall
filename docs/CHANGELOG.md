# 更新记录

## 0.6.12

- 修复快捷方式 / 下拉磁贴偶发无法启动：桌面「一键打开宿舍门」改为每次启动动态刷新，覆盖安装或改名后不再残留失效快捷方式。
- 下拉磁贴改为先解锁再启动，并在直接启动失败时自动回退到系统启动入口、给出可读提示，避免 ColorOS 弹出「应用数据读取失败，无法启动应用」。
- 安装后首次启动引导把 Cumpus 加入电池优化白名单，界面设置新增「允许后台运行（防冻结）」入口，降低 ColorOS 速冻导致的启动失败。
- 提高钥匙站抓取成功率：不再清空 logcat 缓冲，改为回看最近 3 分钟 + 按时间戳过滤，先打开门锁页再点「开始抓取」也能命中。
- 抓取同时监听 main/system/crash 三个日志缓冲，并把内容缓冲改为环形，防止长时监听内存膨胀。
- 解析器兼容官方更多写法：`activation_key`、JSON 引号、`lockKey/openKey`、大写字段名等，降低漏匹配。
- 新增兜底：logcat 未命中时（root 环境）自动扫描官方天猫校园自己的日志文件（TLog），命中即写入结果。
- 抓取界面显示多轮监听进度（共 3 轮），失败信息带上服务端诊断（收到行数 / 匹配数）。

## 0.6.11

- 移除 Cumpus 内“慧生活我的 → 设备与饮水 → 我的”中的“项目地址”和“支持开发者”。
- 胖乖生活扫码对齐原版：同时识别 `NQT`、`IMEI`、`SN`，不再只接受 `NQT`。
- 胖乖生活识别吹风机等服务端 `jumpToDevicePageFlag` 后，按原版参数打开支付宝官方小程序。
- 增加原版 `common/charge/url` 回退，普通设备二维码由服务端解析目标后再打开支付宝。
- 外部目标只允许支付宝 `platformapi/startapp` 官方协议，并固定交给支付宝官方包。
- U净 Nordic 启动现在会检查订单号和启动指令是否真正写入；收尾状态上报失败不再把已写入的启动误报为失败。
- U净点击启动时立即显示连接提示并记录设备、MAC、模块和订单长度，改善无反馈感。
- U净缺少 MAC 或模块类型时会先自动刷新设备详情，不再静默退出；错误提示移到不被底栏遮挡的位置。
- U净点击启动后先再次确认订单已付款；服务端状态延迟时短暂等待并明确提示，不会直接连接蓝牙或看似无响应。

## 0.6.10

- 修复当前 U净账号只提供 `alipayF2F` 时，服务端成功返回 `data.url` 却被误判为参数缺失的问题。
- 识别官方 `alipays://platformapi/startapp` 支付跳转，并固定交给支付宝官方包打开。
- 不再把 `alipayF2F` 跳转交给 `PayTask`，也不会把普通 URL、JSON 或二维码误当 SDK 支付串。
- 仅接受支付宝 `platformapi/startapp` 路径；拒绝其他自定义 scheme，避免订单参数被其他应用截获。
- 服务端返回有效支付跳转后不再误取消订单或尝试重建，修复随后出现的“设备已被占用”。
- 从支付宝返回、切回桌面后重新打开 Cumpus，或用户从最近任务回来时，都会自动查询 U净订单状态。
- 支付宝返回结果只作为“已返回”信号，最终仍以 U净订单和支付状态接口为准。
- 支付失败日志统一脱敏自定义 scheme、URL、Token、支付串和签名。
- 已在 OnePlus PLQ110、Android 16 上验证可以进入支付宝“确认订单”页；验证期间未确认付款或产生扣款。

## 0.6.9

- 重构 U净支付状态机：支付前先确认订单，查询失败不再按未支付处理。
- 渠道缓存绑定订单、设备和服务主体，用户续付时强制刷新，只有实际刷新成功才显示刷新提示。
- 仅允许官方 `alipay` 渠道进入 `PayTask`；`alipayF2F`、网页、二维码和其他渠道明确提示不支持。
- 按官方 `payInfo.orderInfo` 契约解析，支持嵌套对象和 JSON 字符串，不扫描无关字段。
- 支付宝参数串必须包含非空 `app_id`、`biz_content`、`sign`；`sign_type` 不能代替签名。
- 增加 HTTP 状态、业务错误码、字段路径/类型、支付串长度和订单查询结果的脱敏诊断。
- 参数缺失后先复查订单，仅在未支付或超时时安全重建一次，避免卡死和无限重试。
- 重复点击、防重复下单和 6020208 冷却抽成可测试的互斥状态机。
